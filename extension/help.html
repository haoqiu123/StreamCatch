StreamCatchVIDEO DOWNLOAD HELPER
A LITTLE GUIDE

你的网页视频收藏工具。

StreamCatch 会寻找当前网页实际加载的视频。直接在弹窗里选画质、改文件名并点击下载，Mac 助手会自动下载和合并音画。关闭弹窗，下载仍会继续。

没有插件能保证下载所有网站。DRM、访问权限、登录状态、站点策略和视频链接有效期都会影响结果。

01 / 安装浏览器插件

  1. 解压安装包，把 StreamCatch 文件夹放到你打算长期保留的位置。移动文件夹后，需要重新加载扩展。
  2. Chrome 地址栏输入 chrome://extensions；Edge 使用 edge://extensions；Brave 使用 brave://extensions。
  3. 打开「开发者模式」→「加载已解压的扩展程序」，选择 StreamCatch / extension 文件夹。选择包含 manifest.json 的那一层。
  4. 在浏览器拼图菜单中，把 StreamCatch 固定到工具栏。

02 / 在弹窗里下载

  1. 打开视频网页并播放几秒，再点工具栏上的 StreamCatch。
  2. 视频卡片中可以修改文件名、选择最高画质；默认使用最佳可用画质。
  3. 直接点蓝色「下载」按钮，自动使用本地助手，不跳转到其他页面。
  4. 弹窗中显示队列和下载进度，可以取消。关闭弹窗不会停止下载；请保持 Chrome 运行。
  5. 点底部时钟图标查看下载记录，完成后点文件夹图标在 Finder 中显示。移除记录会保留视频文件。
  6. 没有发现视频时，点「重新检测」，或者「没有检测到？」让助手直接解析当前网页。

若需要登录状态，点底部齿轮，在设置中勾选「使用当前网站的登录状态」。下载会自动合并音画，检查实际编码并输出 QuickTime 兼容的 H.264 / AAC MP4。同一 Kaltura 视频的主清单与音画地址会合并成一张卡片。

X / Twitter 信息流

每个视频按独立资源 ID 匹配封面、推文文字、作者和时长；同一视频的清晰度链接合并为一张卡片。点「查看推文」可打开包含该视频的帖子。滚动到当前可见的视频会优先显示。尚未取得封面时显示「暂无封面」，不会用其他视频的图片代替。

03 / 安装 Mac 本地助手

  1. 需要 Homebrew。如果没有，请按其官网说明安装。
  2. 双击安装包中的 安装Mac助手.command。脚本通过 Homebrew 准备缺少的 FFmpeg / Python，并在独立环境从 PyPI 安装 yt-dlp 和浏览器兼容组件。
  3. 安装成功后，重新打开插件弹窗，右上角应显示「本地助手已连接」。
  4. 选择画质并下载。文件保存到 ~/Downloads/StreamCatch，自动合并并保存兼容 MP4；如果某个来源无法封装为 MP4，会明确提示失败。

若 macOS 阻止打开脚本，可右键 → 打开，或在终端输入 zsh 后将该 .command 文件拖入终端并回车。脚本只为当前用户注册助手，无需管理员权限。

更新解析器："$HOME/Library/Application Support/StreamCatch/runtime/bin/python" -m pip install -U "yt-dlp[default]"；FFmpeg 可用 brew upgrade ffmpeg 更新。删除本地助手：双击「卸载Mac助手.command」。已下载的视频和 Homebrew 依赖不会被删除。

Canvas / Instructure 403

Canvas 的播放入口需要在原课程页面中取得授权地址。1.3.1 会在已打开的 Canvas 页面读取媒体信息和跳转地址，并把浏览器取得的未加密 DASH 清单交给本地助手下载分片；不需要导出登录 Cookie。同一播放器的 DASH、跳转入口和更新的签名链接合并为一张卡片，点击下载时重新取得有效入口。若页面要求重新登录或验证，请在原网页完成，再点「重新检测」。本地助手需更新至 1.3.1，并安装 yt-dlp 支持的 curl_cffi 浏览器兼容网络组件。

重复卡片与 Bilibili 下载

1.4.0 按 YouTube / Bilibili 的明确视频 ID 和单视频网页合并入口；同一视频的清晰度由下拉框选择。重新检测会丢弃旧来源，切换视频会清理旧记录。Bilibili 英文链接会转为对应 BV / 分 P 入口；新版页面通过普通视频信息接口解析，遇到主线路中断会尝试接口提供的备用线路。下载在独立临时目录进行，检查实际音画、全片解码和时长后才保存 MP4；不会复用之前的残片或覆盖已有文件。

HTTP 403 与受保护的视频

403 表示服务器拒绝读取，不足以判断是否使用 DRM。插件只转交对应媒体请求中的 Referer、Origin、User-Agent；不会通过网络观察收集 Cookie 或 Authorization。需要登录的非 DRM 媒体可在设置中选择「使用当前网站的登录状态」，通过浏览器授权后再下载。请先回原网页正常播放并重新检测以更新有效链接。DRM 检测会明确提示，不提供密钥提取或 CDM 破解。

QuickTime 只有声音 / 提示不兼容

MP4 文件也可能包含 VP9、AV1 等视频编码。1.2.1 本地助手会检查真实音画轨道，将不兼容视频转换为 H.264、音频转换为 AAC；已经兼容的轨道直接保留。转换期间可在弹窗查看进度或取消，检查通过后才显示完成。YouTube 的单独音轨链接会优先交给原视频网页解析，避免只保存声音。升级插件后请更新 Mac 助手使其生效。

下载失败时

  • 401 / 403：确认原网页仍可播放，刷新并重新检测；尝试本地助手并勾选登录状态。需要特殊请求头的网站仍可能失败。
  • 只检测到 blob：它通常不是完整文件地址。播放视频后重新检测，或解析原网页。纯内存视频、WebRTC、封闭播放器可能无法处理。
  • 没有声音：从主 HLS 播放列表或原网页使用本地助手下载，避免仅下载独立的视频轨道。
  • TS 无法在默认播放器中打开：用支持 TS 的播放器，或通过本地助手重新下载、封装。
  • 助手连接失败：检查安装脚本是否完成，扩展文件是否完整，重新打开弹窗；Homebrew 更新 Python 后可重新运行安装脚本。

数据与权限

视频和 Cookie 不上传到第三方服务。插件需要网站访问和网络观察权限，才能检测跨域播放器。检测列表只放在本次浏览器会话中，清空检测、关闭标签页或结束浏览器会话可移除相应记录。下载工作台来源信息保留在本次会话中，便于刷新恢复。

Cookie 权限是可选的，仅在你勾选登录状态并点击本地下载时申请。只读取与当前页面和视频地址匹配的 Cookie，经浏览器原生消息交给本机助手，以仅当前用户可读的临时文件传给 yt-dlp；任务结束后删除。浏览器直链下载和 HLS 请求可能自动携带该网站的现有登录 Cookie。最近 30 条下载记录保存在插件本机存储中；记录包含文件名、状态和本地路径，不保存带签名的视频链接或 Cookie。插件或浏览器重启后，未完成任务标为中断，不会自动继续。

本地助手只接收这个扩展的原生消息，不开放本地网络端口，不接受远程脚本或任意终端命令。

视频入口过期 / HTTP 404

回到原网页刷新并播放几秒，然后打开弹窗点击「重新检测」并重新下载。插件会尝试更新同一 Kaltura 视频的入口。404 表示相应资源不存在或已经失效；助手在独立临时目录下载，失败时不发布成品；重新下载不会复用先前残片。
